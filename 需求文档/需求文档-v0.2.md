## 一、项目概述

**项目目标**：让处于低了解、低信任状态的访客，在短时间内意识到第一次介绍中的机会损失，通过可操作的个人网站演示理解产品如何建立可信的了解入口，看清三档交付差异、价格与服务流程，并最终预约定制个人网站。

**核心结果**：预约定制个人网站。品牌认知、产品演示、交付证据、方案价格与流程说明都服务于这一行动；每项内容必须推动「与我有关 → 看见产品 → 理解机制 → 认可价值 → 选择方案 → 愿意预约」中的至少一步。访谈与问卷是预约后的需求采集方式，不是官网的最终转化目标。

**目标受众**：所有需要被立体认识的人。访客通常只有有限时间与零散信息，尚未建立对品类与品牌的认知。

**技术栈**：React + Vite + 纯 CSS（不引入 UI 组件库），单页应用。

**交付物**：本地可运行的前端项目，适配桌面、平板、手机三种尺寸。

**风格参考**：linear.app 的秩序感与近黑白灰层级（细边框、留白、精致排版、克制动效）；品牌 Brief v2 视觉识别系统的哑光金、字体、栅格与组件纪律。

## 二、品牌口径

官网说什么、怎么说，以此节为准（依据 Brief v2 与 CEO 2026-10-25 会议决议）：

- **一句话定位**：为需要被立体认识的人，打造可识别、可信任的个人数字身份。
- **产品交付**：以完整的定制个人网站承载个人数字身份，包含首页、关于、作品 / 论文 / 项目展示、联系方式等页面；交付源码与部署教程。官网以明确标注的虚构人物和内容演示产品，不把演示包装为客户案例。
- **核心承诺**：让第一印象，经得起了解。
- **认知主词**：「多面」。多面不是展示更多内容，而是让不同对象在不同场景里，找到与其相关、且有依据的你。
- **命名规范**：全称固定语序「多面派 · Youniverse」；三种写法——YOUniverse（主体全称、合同抬头、公司介绍页首屏）、YOUNIVERSE（视觉识别、logo 字标、KV）、Youniverse（叙述体、正文提及）。禁止 Studio / Lab / 工作室 / 科技等变体。
- **中英分工**：中文负责立场与身份，英文负责世界与延展。
- **叙事主轴**：第一次介绍发生在信息有限、注意力有限的情境中。零散信息让对方难以继续了解，缺乏依据让信任难以开始。个人数字身份以统一入口降低认识成本，以多面结构呈现相关重点，以证据链降低核验成本，再把持续增加的经历、作品与信任沉淀为长期数字资产。
- **文案语态**：陈述式短句，平行节奏，克制留白。痛点写具体损失，解法写清楚机制，不用无依据的比例、绝对因果与结果保证。
- **信息增量**：每句可见文案都要提供具体对象、动作、内容或结果。删掉后不损失理解的重复标题、空泛收束句与操作提示不进入页面；操作提示直接说明点选什么、页面会发生什么。
- **禁用表述**：不得使用「建站公司 / 网页工作室 / 简历优化」等品类降级说法。

## 四、视觉设计规范

### 4.1 基调

暗色高质感 + Linear 秩序感。底色为近黑中性色（Linear 同款，非纯黑、不带蓝调），雾白文字、灰阶分层、细边框、留白、精致排版、克制动效为骨架；哑光金为全站唯一强调色；全站以细线为第一视觉语言（见 4.4.1）。整体气质是专业、克制、现代，而非科技秀场。

### 4.2 色彩系统（近黑白灰层级 + 品牌哑光金）

| 角色 | 色值 | 官网用途 |
| --- | --- | --- |
| 页面背景 · 近黑 | #08090a | 全站底色（Linear 同款中性近黑，无蓝调） |
| 面板 / 卡片 | #141416 | 卡片、浮层、导航底（微亮一层） |
| 边框 | rgba(255,255,255,0.08) | 1px 细分隔线 |
| 正文文字 · 雾白 | #f7f8f8 | 主内容与标题 |
| 次级文字 | #8a8f98 | 说明、辅助信息 |
| 弱文字 | #62666d | 标签、注释（仅限非关键信息，对比度偏低） |
| 强调色 · 哑光金 | #b08d57 | 强调线、关键节点、hover 态与背景光晕，沿用品牌 Brief 色值 |
| 强调文字 · 香槟金 | #d2b985 | 英文小标、序号、标签与价格等深底小字，保证可读性 |
| 辅助金 · 深金 | #8f6e3f | 低透明度环境光与色彩层次，不用于正文 |

**纪律**：金色只做强调不做主体；渐变只允许出现在背景，不得进入 logo 图形；禁止玻璃拟态、霓虹赛博与大面积高亮金色。对比度底线：文字与底色 ≥ 4.5:1，大字（≥18pt）≥ 3:1；弱文字 #62666d 不得用于关键信息。

### 4.3 字体

- 标题（中文与英文同源）：思源黑体 Source Han Sans SC Heavy / Bold。中英标题同源是 Brief 的重要决策，避免混排字重跳变。
- 正文中文：字体栈 "Source Han Sans SC", "PingFang SC", "Microsoft YaHei", "Hiragino Sans GB", sans-serif；Windows 以等线兜底。
- 品牌英文名与标识性文本：等宽字体 Consolas / Menlo / Courier New——强化「这是一个命名」的感觉，用于 YOUNIVERSE 字标、系列名等。
- 英文全大写短句（如 YOUNIVERSE、英文小标）：Light/Regular 字重，禁止 Bold（全大写粗字重显喧哗）；字距 +0.24em 至 +0.30em；两短句之间用句号，不用斜杠或中点。
- 数字：等宽数字特性（tabular-nums）保证对齐。
- 字号层级：Hero 中文标题桌面不超过 64px、字重约 560–600，字距与行高按中文笔画密度单独校准，不机械套用英文负字距；区块标题 34–46px；正文 15–16px；辅助信息不低于 13px；英文小标（kicker）11–12px、全大写 + 宽字距。价格、交付、原价、预约方式等决策信息不得使用弱文字或装饰性小字。

### 4.4 组件规范

- 栅格：1440 基准，12 栏，内容最大宽 1200px 居中，左右最小留白 40px（移动端 20px）；垂直间距取 8 的倍数（8/16/24/32/48/64）。
- 对齐纪律：全局左对齐与两端对齐，禁止居中对齐正文（仅标题、短句可用居中）。
- 主按钮：雾白底 #f7f8f8 + 近黑字 #08090a（Linear 主按钮做法）；hover 底微降至 #e9eaec；高 40px（移动端 48px）；内边距 24px 32px；圆角 2px；字号 15px/500。每屏最多一个主按钮，禁止反色使用。
- 次按钮：透明底 + 1px 描边（深底上用白描边）+ 白字；hover 填充 5% 灰，不改变描边粗细。
- 文字按钮：无边框，hover 加下划线，用于「了解更多」类辅助动作。
- 卡片：圆角 4px；内边距 24px；卡片底 #141416 + 1px 边框 rgba(255,255,255,0.08)；卡片标题 17px/700，正文 14px/1.7。禁止重阴影、禁止彩色卡片背景。
- 标签：金色系（文字 #d2b985 / 底 rgba(176,141,87,0.10) / 边 rgba(176,141,87,0.28)）与中性灰（文字 #8a8f98 / 底 rgba(255,255,255,0.06) / 边 rgba(255,255,255,0.10)）两种；警示类保留红色。
- 引用/引文：左侧 2px 哑光金 #b08d57 竖线 + 左内边距 20px；引文必须可溯源。
- 分隔线：1px，深底 rgba(255,255,255,0.14)；不使用双线与粗线。
- 产品演示：使用完整浏览器窗口与独立内容画布，清楚呈现导航、首页、关于、作品和证据关系；演示人物与内容统一标注为虚构。支持页面切换、桌面 / 手机预览和证据路径点选，控件具有明确选中态、键盘焦点与可访问名称。
- 方案比较：价格卡负责快速选择，比较表负责核对差异；移动端按档位查看比较内容，不压缩为不可读的小字表格。每档都有独立预约入口，并自动带入方案名称。
- 流程与 FAQ：流程使用连续步骤而非重复卡片；FAQ 使用原生可展开控件，回答交付、预览、修改、部署、素材授权与预约支付等实际问题。

### 4.4.1 线条语言

全站以细线为第一视觉语言，线即结构、线即装饰、线即形状（品牌形状见 4.4.2）：

- 细线分层：1px 边框与分隔线为常态，hairline（0.5px 级，视设备渲染）用于卡片内部细分与装饰性结构线。
- 装饰图形一律用线条绘制（轮廓式、线框式），不用填充块面、不用大色块；渐变只留在背景光晕里，不进图形。
- 多角度几何投影改用线框表达：同一主体 2–3 个角度，只画轮廓线与关键结构线，可叠化、可错位重叠。
- 工程图式辅助线与网格允许作为装饰（Linear 线框示意图的气质），密度克制，只做分区与呼应，不做底纹铺满。
- 线条颜色：结构线用白 / 灰低透明度（rgba(255,255,255,0.08–0.14)），强调线与激活态用哑光金 #b08d57。
- 图纸标注感细节（小圆点节点、短刻度、十字参考点）可少量使用，起「精致标注」作用，不喧宾夺主。

### 4.4.2 线条品牌形状

细线不只做分隔，还用来绘制品牌形状——以下形状词汇全部用线框绘制，构成「多面 + 宇宙」世界观的可视语言：

- 多面体线框（核心图形）：正多面体 / 多面体的线框透视图，是「多面」的直接图形表达；用于区块装饰与资产卡片。每个图形只保留外轮廓和揭示体积所需的关键结构线。
- 切面图形：多边形切面线框（三角 / 菱形 / 六边形），表达「面向」——同一主体的不同面向。切面作为独立构图使用，以一个大形和一处金色结构线形成视觉重点。
- 轨道圆环：单线椭圆轨道，表达宇宙场域。一条主轨道确定构图方向，可配一条更细、更淡的副轨道增加空间层次；两条轨道采用不同倾角，避免形成密集网格。
- 星球关系：主视觉采用「一个星球 + 主副双轨道 + 一道月牙切面 + 至多一个卫星」的适中密度构图。主轨道穿过星球时以后景弧线、星球本体、前景弧线分层，形成前后遮挡；副轨道保持低透明度，月牙切面是星球内部唯一结构线，以轮廓、遮挡和大小关系体现体积。该语言用于装饰图形，不代表已选定任何一款正式 Logo。
- 星点关系：少量星点以单条细线连接，用于小尺寸线性图形；每幅小图至多三个节点与一条关系线，关键节点可用哑光金。
- 多角度投影：同一主体的线框视图错位叠放（与 4.6 呼应），是「多面」的叙事手法；小尺寸场景优先使用单视图，保证轮廓清晰。
- 构图纪律：同一装饰画面聚焦一个主图形，切面与轨道分别构成不同场景；主体周围保留充足留白。一律使用线框 / 轮廓线，无渐变；背景同色填充只用于形成轨道遮挡；金色只作强调线或关键节点，形状保持几何秩序。

### 4.5 动效（克制路线）

- 星空：近黑底 #08090a + 极少量极小星点（星点直径 ≤ 画面宽 0.3%，数量 5–15 个，亮度分级，冷白 / 香槟金），极缓慢漂移，纯 CSS 实现。
- 轻量装饰视差（CEO 拍板，Brief 视差红线改为例外）：星点层与星云层以不同速度随滚动轻微错位，营造纵深；区块内装饰图形（金色光点、多角度几何投影）随滚动做轻微位移。实现用 CSS transform，无重排、无重型库。
- 滚动渐显：区块进入视口时淡入 + 轻微上移（IntersectionObserver）。
- 悬停微交互：150–200ms 过渡；hover 用哑光金做辅助强调。
- 明确不做：3D 效果（红线：留作私聊钩子）；发光网格、粒子特效、数据流（蓝色科技风红线）；整段背景的明显视差与重型动画。

### 4.6 图像与背景风格

- 底色以近黑中性 #08090a 为基底，整体曝光偏暗（暗 1/3 至 1/2 档），暗部保留细节。
- 光源：单一主光 + 环境反射光，允许冷白或少量哑光金光；避免均匀柔光箱肖像感。
- 星点：负空间极小光点，5–15 个，亮度分级，后期叠加。
- 多角度投影：同一个人物 / 作品在同一画面出现 2–3 次、取不同角度——这是全系统最能表达「多面」的手法，优先用线框 / 轮廓线绘制（见 4.4.1），可用叠化、半透明重影或三联画分割实现。
- 色彩：整体低饱和，哑光金为唯一强调色；调色走「暗部中性近黑 + 高光冷白与暖金」。
- 红线：不蓝色科技风（发光网格 / 全息 UI / 电路板 / 粒子特效）；不握手 / 会议室商务图；不渐变紫网红风（玻璃拟态 / 赛博霓虹）；不摆拍精英人设照；图像上不叠加大段文字（≤ 12 个汉字）。
